What the knowledge base holds

Agents read the index. It is built from your notes by a sync. A fact on disk that the index does not hold yet is marked, and agents cannot find it until the next sync.

How to read the Merkle tree
  1. Leaf: one fact, meaning a paragraph, a list item, a table or a code block. Its fingerprint is a BLAKE3 hash of its words. Case, spacing and sentence punctuation are ignored, so formatting-only edits keep it.
  2. Note: its hash covers its fingerprints in order, each labelled with the headings above it. Changing a fact, or moving it under another heading, changes the note hash.
  3. Root: one hash over every note hash and its path. When the root of your notes equals the root the index holds, the index has every fact.

Adding, replacing or removing a fact here changes the note, then syncs: the tree is rebuilt and the changed note lights up. Click any hash to copy it.
