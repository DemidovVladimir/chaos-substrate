The index file

The index is one redb file, by default <vault>/.chaos-kb/index.redb. It holds the Merkle tree, the chunks, their vectors and the block fingerprints. A sync rewrites it in one transaction. Delete it, and the next sync rebuilds it.

  • 5 tables in 1 file
  • 1 write transaction per sync
  • waits up to 3 s for a held file, first pause 10 ms
  • vectors as 4-byte little-endian floats
  • data the index file and its tables

How a sync replaces the index

redb is an embedded database written in Rust: one file, no server. A transaction is a group of changes that is saved all at once or not at all.

A chunk's key comes from its context line and text only. Two notes with the same title, section and words, such as x/Plan.md and y/Plan.md, share one chunks row. A search then names one of the two notes, while a same-words check lists both.

Try it: hold the file

Sharing the file

redb lets one handle open the file at a time, so every operation opens it and closes it right after. Say another process holds the file: move the slider to when it lets go.

100 ms

Tries start at 0, 10, 30, 70, 150, 310, 630, 1270 and 2550 ms: each pause doubles, from 10 ms. The last try is at 3000 ms; after it the command fails with index <path> is held open by another process; gave up after 3s, naming the file. Times leave out the open itself.

Outcomes

What the file can be

  • noneno file yetReads find nothing and create nothing; check and search say to run sync.
  • nonean empty fileRead as no file, until a sync fills it.
  • waitheld by another processRetried for up to 3 s, then an error that names the file.
  • refusea chunk without a vectorThe write stops and the index is unchanged.
  • refusea query of another lengthThe stored vector's length is named, with a hint about the embedder.
  • errora row that does not decodeAn error, never a crash or a wrong answer.
Enforced in code

Guarantees

  • Derived and disposable. The notes are the knowledge. Delete the file and the next sync rebuilds it with the same root.
  • All or nothing. A sync writes in one transaction, so the file holds the old index or the new one.
  • No orphans. A vector that no chunk uses is dropped in the same write.
  • Nothing trusted on read. A stored note path must be valid, a chunk row must hash to its key, and a vector must be whole 4-byte numbers.
  • One vector space per file. meta records the embedder id, and reads with another id are refused.
  • Shared, one at a time. The CLI and a running MCP server open the file only for the length of one operation.
Try it

Delete it, rebuild it

On a copy of the example vault after its edits. JSON is shown condensed. The file size is an example; for a vault of 502 notes the index was 8.4 MB (README § Speed).

$ wc -c .chaos-kb/index.redb
  118784 .chaos-kb/index.redb
$ rm -r .chaos-kb && chaos-kb sync
{ "added": ["Car.md", "Talking.md"], "notes": 2, "chunks": 4, "embedded": 4,
  "root": "e4fca44df7c874f52891a89552a6b14ba6e0aceb06e631a21ea0576459b97301" }
# the same root as before the delete: the notes did not change
$ chaos-kb check "x" --index ./none.redb
error: the index is empty: run `chaos-kb sync` first

Use --index or CHAOS_KB_INDEX to keep the file somewhere else. A missing file is not created by a read.
