The dashboard

chaos-kb dashboard serves one web page on your own machine. It shows every note and fact the knowledge base holds and whether the index is up to date, and lets you add, replace and remove facts. Every change syncs the index, so what the page shows is what agents find.

One removal, step by step

From a click to a changed note

127.0.0.1 is the address a computer uses for itself, so no other machine can reach the page. The page changes your notes only by calling the same tools an agent calls, here kb_forget.

What you see

Your notes next to the index

A fingerprint is a hash of one block's words. Each note gets one hash over its fingerprints. Agents read the index, which a sync builds from the notes, so the page shows each note's hash twice: from the note on disk now, and as the index holds it. Where the two differ, the index is behind.

The status line

Is the index up to date?

The line at the top of the page says it in one sentence. A banner below it says what to do.

  • okIn sync: agents see every fact belowEvery note's hash equals the one the index holds, and the vectors were made by the embedding model set now.
  • behind2 notes not in the index yetNotes were added, changed or deleted on disk since the last sync. The banner lists them, with a Sync now link.
  • emptyNot indexed yetNo sync has run, so agents find nothing.
  • modelEmbedding model changedThe index was built with another model. Same-word checks still work; search by meaning waits for a sync, which embeds every passage again.
  • goneDashboard server not reachableThe page cannot reach chaos-kb dashboard, for example after Ctrl-C.
The controls

Add, replace, remove, ask

Each control calls a tool exactly as an agent does. After a change the page reads the overview again, and the notes whose hash changed light up.

Add a fact

Runs remember with the fact, a note (Inbox.md when left empty) and an optional heading. When the same words are already stored, nothing is written and the page says where they are. When the index cannot take the fact (Ollama not running, say), nothing is written either, and the page shows why. The vault

Replace

Edits a fact. The page first runs remember with the new text under the fact's innermost heading, then forget with the old words in that note, so a refused new text leaves the old fact in place. Nothing changes when the words are the same.

Remove

Runs forget with the fact's words, only in its note, after a confirm on the page itself. Other notes keep their copy. How forget removes

Sync now

Runs sync, for edits made in Obsidian or any editor. The page does it on its own while auto-sync is on.

Try a question

Runs check and topics as an agent would: known or not, with the similarity and the 0.38 line, and the closest passages. Click one to open its note at its facts. How check decides

Filter, expand

Narrow the list to notes and facts holding some words, or open every note at once. A note stays open across redraws.

Switch knowledge base

Choosing another name in the header reads that knowledge base's overview (GET /api/overview?instance=NAME) and sends instance with every tool call from then on, so an added or removed fact lands in the vault shown. The page disables the switch while a change runs. Several knowledge bases

Replace puts the new text at the end of that heading's own text, as remember does, so the fact can move down a few lines. A fact above the first heading has no heading, so its new text goes at the end of the note.

Edits made elsewhere

Auto-sync

Every 4 seconds, while the tab is visible, the page reads the overview again. An edit made in another app shows up as changed or new. The checkbox Sync edits made outside the dashboard decides what happens next.

  • onticked, the defaultWhen the notes differ from the index, the page syncs on its own and logs it as Automatic sync. This browser remembers the choice.
  • offuntickedThe page still looks every 4 seconds and shows what is pending; you sync with the button.
  • pausedan automatic sync failedOllama stopped, say. The page does not try again until the notes change again or you flip the checkbox; the banner points at the error in Activity.
  • quietnothing changedAn overview equal to the last one draws nothing, so a half-typed replacement survives every look.
Enforced in code

Safety rules

A web page in another tab can send requests to 127.0.0.1 too. These rules keep such a page from reading or changing your notes.

  • This machine only. The server listens on 127.0.0.1, never on an address other computers can reach.
  • Its own name only. Every request must be addressed to 127.0.0.1:<port> or localhost:<port> (the Host header), or it gets 403. That stops a site that points a domain name of its own at 127.0.0.1.
  • Tools take JSON from this page only. POST /api/tools/kb_<tool> needs Content-Type: application/json (415 otherwise) and refuses another page's Origin (403). A browser sends JSON to another site only after asking first, and this server never says yes.
  • Nothing from elsewhere. The page is one file built into the binary, with its own styles and script. Its Content-Security-Policy header allows only those and calls back to this server: no other site, no frames, no forms.
  • Notes stay text. Words from a note are put on the page as text, never read as HTML.
  • One thread per connection. Each connection carries one request and is closed after the answer. A connection silent for 10 s is dropped.
  • Requests are bounded. Headers up to 16 KiB (431), a body up to 1 MiB (413), and only with a Content-Length (501 for a chunked body).
  • Same locks as everyone. Each request opens the knowledge base it names afresh, as a command does, so the dashboard, the CLI and an MCP server take turns on one vault.

Try it

Start it, then talk to it by hand

On the small vault from the forget example, right after it. The page does the same calls; curl only shows them.

$ chaos-kb dashboard &
chaos-kb dashboard: http://127.0.0.1:7341/ (Ctrl-C stops it)
$ curl -s http://127.0.0.1:7341/api/overview | jq -c '{synced, pending, chunks, vectors}'
{"synced":true,"pending":{"added":[],"changed":[],"removed":[]},"chunks":5,"vectors":5}
$ curl -s -H 'Content-Type: application/json' -d '{"text":"Tyres: 205/55 R16.","note":"Car","heading":"Tyres"}' http://127.0.0.1:7341/api/tools/kb_remember
{"embedded":1,"note":"Car.md","stored":true}
$ curl -s -H 'Content-Type: application/json' -d '{"text":"Tea, no sugar.","note":"Inbox.md"}' http://127.0.0.1:7341/api/tools/kb_forget
{"embedded":0,"removed":[{"lines":[3,3],"note":"Inbox.md","section":"Inbox"}]}
$ printf '\nGreen tea after lunch.\n' >> Inbox.md
$ curl -s http://127.0.0.1:7341/api/overview | jq -c '{synced, pending}'
{"synced":false,"pending":{"added":[],"changed":["Inbox.md"],"removed":[]}}
$ curl -s -H 'Content-Type: application/json' -d '{}' http://127.0.0.1:7341/api/tools/kb_sync
{"added":[],"changed":["Inbox.md"],"chunks":6,"dry_run":false,"embedded":1,"notes":4,"removed":[]}
$ curl -s -w ' %{http_code}\n' -H 'Content-Type: text/plain' -d '{}' http://127.0.0.1:7341/api/tools/kb_sync
{"error":"send the arguments as application/json"} 415
$ curl -s -w ' %{http_code}\n' -H 'Host: attacker.example:7341' http://127.0.0.1:7341/api/overview
{"error":"this dashboard answers requests to http://127.0.0.1:7341 only"} 403
$ curl -s -w ' %{http_code}\n' -H 'Content-Type: application/json' -H 'Origin: https://attacker.example' -d '{}' http://127.0.0.1:7341/api/tools/kb_sync
{"error":"tools answer this dashboard's own page only"} 403

Forgetting Tea, no sugar. embedded nothing: it was the only fact in Inbox.md, so that passage was simply dropped, and # Inbox stayed. The edit made with printf showed up as changed before any sync; with the page open and auto-sync on, it would have been synced within 4 seconds. These commands assume CHAOS_KB_VAULT points at the vault and run inside it.

With two knowledge bases, the overview and the tools take the instance by name. Another sample run, on two small vaults:

$ chaos-kb --vault personal=kb/personal --vault molecule=kb/molecule dashboard --port 7394 &
chaos-kb dashboard: http://127.0.0.1:7394/ (Ctrl-C stops it)
$ curl -s http://127.0.0.1:7394/api/overview | jq -c '{instance, instances: [.instances[] | {name, default}], notes: [.notes[].path]}'
{"instance":"personal","instances":[{"name":"personal","default":true},{"name":"molecule","default":false}],"notes":["Car.md","Inbox.md"]}
$ curl -s 'http://127.0.0.1:7394/api/overview?instance=molecule' | jq -c '{instance, notes: [.notes[].path]}'
{"instance":"molecule","notes":["Lab.md"]}
$ curl -s -H 'Content-Type: application/json' -d '{"dry_run":true,"instance":"molecule"}' http://127.0.0.1:7394/api/tools/kb_sync
{"added":[],"changed":[],"chunks":1,"dry_run":true,"embedded":0,"instance":"molecule","notes":1,"removed":[]}
$ curl -s -w ' %{http_code}\n' 'http://127.0.0.1:7394/api/overview?instance=work'
{"error":"no instance is named `work`; the instances are `personal`, `molecule`"} 500
