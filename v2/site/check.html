How check decides

check answers one question: is this already known? When every block of it is stored word for word, the answer is exact, with no model call. Otherwise the best of the three nearest passages must score at least 0.38.

  • 3 answers: exact, similar, absent
  • 3 nearest passages compared
  • known from a score of 0.38, inclusive
  • 0 model calls for the same words

One check, step by step

Same words first, then meaning

A score is the cosine similarity of the question and a passage: 1 means the same direction of meaning, 0 means unrelated. See Chunks, embeddings and search.

Where 0.38 comes from

The questions of tests/e2e.rs, eight that the vault answers and seven that it does not. Scores as printed by cargo test --release --test e2e on 2026-10-24, measured on an Apple M4 with Ollama 0.24.0 and embeddinggemma.

0.38

The default sits in the gap between the weakest answered question, 0.419, and the strongest near miss, do I have a pilot licence? at 0.345. The gap is narrow, so treat similar as "probably known: read it". Some paraphrases fall below the line: can I drive a car legally? scored 0.314816415309906 on the same vault. Another embedding model needs its own --min-score.

Outcomes

Answers and refusals

  • exactevery block is storedKnown. Every place is listed; no score.
  • similarbest score at or above the lineKnown. Read the matches before you rely on them.
  • absentbest score below the lineNot known. The score shows how close it came.
  • errorblank querythe query is empty (no letters or digits)
  • errorno index yetthe index is empty: run `chaos-kb sync` first
  • erroranother model, by meaningSame words still answer exact. A check by meaning names the index's embedder id and asks for a sync.
Enforced in code

Guarantees

  • An exact match wins. Whatever any score would say, the same words mean exact.
  • Exact means every block. A query of two facts is exact only when both are stored; otherwise the whole query is judged by meaning.
  • The same words need no model. The exact path works before Ollama runs and after a model change.
  • The line is inclusive. A score equal to min_score is similar.
  • Nothing is not a match. No passage, or a score that is not a number, is absent.
  • Matches are never weaker than the line. Passages below min_score are left out of matches.
  • Only absent is unknown. known is true for exact and similar.
Try it

Check the example vault

JSON is shown condensed. A check by meaning took 0.14 s and a check by the same words 0.04 s on a vault of 503 notes, measured on an Apple M4 (README § Speed).

$ chaos-kb check "allergic to PENICILLIN"
{ "known": true, "presence": "exact", "matches": [ { "note": "Health/Allergies.md", "section": "Allergies", "lines": [3, 3] } ], ... }
$ chaos-kb check "how often do I change the oil?"
{ "known": true, "presence": "similar", "score": 0.583015501499176, "matches": [ { "note": "Car.md", ... } ], ... }
$ chaos-kb check "how often do I change the oil?" --min-score 0.6
{ "known": false, "presence": "absent", "score": 0.583015501499176, "matches": [], ... }
$ chaos-kb check "what is the name of my dog?"
{ "known": false, "presence": "absent", "score": 0.20223255455493927, "matches": [], ... }
$ chaos-kb check "  ---  "
error: the query is empty (no letters or digits)
$ chaos-kb check "allergic to PENICILLIN" --embed-model nomic-embed-text
{ "known": true, "presence": "exact", "matches": [ { "note": "Health/Allergies.md", "section": "Allergies", "lines": [3, 3] } ], ... }
$ chaos-kb check "how often do I change the oil?" --embed-model nomic-embed-text
error: the index was built with embedder `embeddinggemma|gemma-retrieval-v1` but `nomic-embed-text|plain-v1` is configured: run `chaos-kb sync` to re-embed

A query that starts with - needs -- before it on the command line: chaos-kb check -- "- **Allergic** to *penicillin*!" answers exact. Over MCP the query is always passed as text.
