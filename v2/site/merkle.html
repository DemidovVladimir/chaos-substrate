Merkle tree and exact check

A fingerprint is a hash of the words in one block. Fingerprints roll up, note by note, into one root hash for the whole vault. The same words take one lookup, and an unchanged root means nothing changed.

  • hash: BLAKE3, 32 bytes, 64 hex characters
  • leaf tag 0x00, node tag 0x01
  • 0 model calls on the exact path

One sync, then one lookup

From words to one root

A hash is a short, fixed-size value computed from data: equal data gives an equal hash. A Merkle tree is a tree of hashes in which each parent hashes its children.

What a sync sees

Edits and their hashes

The sync report lists notes only. The root tells whether anything changed at all.

  • sameformatting onlyBold, a list marker, extra spaces: every hash stays. The chunk text changed, so that chunk is embedded again.
  • changedwords editedThe note's hash and the root change. Every other note keeps its hash.
  • changeda fact moved under another headingIts label changes, so the note changes.
  • changedtwo facts swappedOrder is part of a note, so the note changes.
  • addeda note renamedThe new name is added, the old one removed, and the root changes.
  • removeda note deletedThe root changes and its fingerprints leave the exact index.
Enforced in code

Guarantees

  • Formatting never moves a hash. Blocks are hashed as plain words, so Markdown marks, case and spacing do not count.
  • Words, order, headings and names count. Change any of them and the note's hash and the root change.
  • No mix-ups by construction. Leaves and nodes start with different tag bytes, and every label carries its length.
  • Blank blocks are not knowledge. A rule or an empty item never enters the tree or the exact index.
  • The exact path is free. It reads the stored fingerprints and never calls the embedding model.
  • Hashes are always whole. They print as 64 lowercase hex characters, and nothing shorter is accepted.
