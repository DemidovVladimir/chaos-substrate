The vault

The vault is a folder of Markdown notes, as Obsidian keeps them. chaos-kb reads every visible note, whole, and splits it into blocks. It writes only when you call remember, which adds text, or forget, which takes blocks out.

  • facts go to Inbox.md unless you name a note
  • 1 writer at a time, by .chaos-kb/append.lock
  • 1 temporary file and 1 rename per write
  • 2 calls write notes: remember and forget

One remember, step by step

A fact goes into a note

A heading's own text is what sits right under it, before the next heading of any level. That is where remember puts a fact, so it reads under exactly that heading.

How a note is read

The rule --- on line 16 has no text, so it is no block. Headings are not blocks: they become the section of the blocks below them. A link's destination is part of the text, so pointing a link somewhere else is a new fact; a link whose label is its destination, such as [[Doctor]], reads once. An HTML block is a block too, read without its tags.

The context line is the note title (the file name) and then the section. A first heading that only repeats the title, like # Medications here, is left out.

    forget
    
Taking a fact out

    
forget is the other call that writes a note. It removes every block with the same words as its text, compared as fingerprints: case, spacing and punctuation aside, and never a passage that only means the same. With --note, only that note is touched.

  

  
    
    
  • foundthe same wordsEvery block with them goes, in every note or only in --note. removed lists where each one sat.
    • 
    
  • noneno block has those wordsNothing is written. removed is empty and not_found holds the text.
    • 
    
  • lineswhole linesA removed block takes its whole lines and one blank line, so its neighbours keep one blank line between them. One list item goes; the rest of the list stays.
    • 
    
  • headingheadings stayRemoving the last fact under a heading leaves the heading in place.
    • 
    
  • movedthe note changed since it was readRefused: those lines no longer hold the words. Nothing is written.
    • 
    
  • readsthe rest would read differentlyRefused, for example when an indented paragraph would join the list item above it. Nothing is written.
    • 
    
  • filea read-only note, or one that is not valid UTF-8Refused, as for remember. Nothing is written.
    • 
    
  • undoa later note refuses, or the index cannot followEvery note already rewritten is put back, byte for byte, and the call fails with nothing was changed: and the cause.
    • 
  

  
Like remember, forget syncs before and after: the first sync makes your own edits count, the second takes the removal into the index. It holds the same .chaos-kb/append.lock, and the note is rewritten through a temporary file that keeps its permissions, then a rename. To correct a fact, forget it in its stored words, then remember the new one; the dashboard's Replace does both.

Which note paths are allowed

    
Every path from disk or from an agent is checked by these rules first, so nothing can name a file outside the vault or in a hidden folder. This runs the rules of src/domain/path.rs in your browser.

  

  

    
    

    

  






  

    What sync reads
    
Files the vault skips

    
The vault walks every folder and keeps only what is a note.

  

  
    
    
  • skiphidden namesFiles and folders whose names start with ., such as .obsidian and .chaos-kb.
    • 
    
  • skipsymlinksA linked file or folder is never followed.
    • 
    
  • skipother filesOnly names ending in .md, in any case, are notes.
    • 
    
  • skipnames the path rules refuse or would changeA name holding : or \, one starting with a space, or one that is not valid UTF-8. Without : in a path, a passage id such as Car.md:8-8 always splits at its last colon.
    • 
    
  • readany sizeEvery note is read whole, however long it is.
    • 
    
  • readbroken textBytes that are not valid UTF-8 are read as replacement characters.
    • 
  






  

    Enforced in code
    
Guarantees

  

  
    
    
  • Only remember and forget write notes. sync, check, search, topics and read never change a note, and neither does the dashboard except through those two.
    • 
    
  • Existing text stays byte for byte. remember inserts its text and one blank line around it; forget takes out only the removed blocks' own lines and one blank line each. Nothing else moves.
    • 
    
  • The rest of the note reads the same. Text that would hide or re-nest what follows, such as an unclosed code fence or HTML comment, or a heading that takes in later sections, is refused. So is a removal after which a kept block or heading would read differently.
    • 
    
  • Only the same words go. forget looks its text up by fingerprint and removes a block only while its lines still hold those words; a passage that only means the same is never touched.
    • 
    
  • A failed sync puts the notes back. When the sync after a write fails, remember and forget put each note back byte for byte and remove a note or folder they created, so the vault and the index still agree. A note someone edited in the meantime is left as it is, and the error names it instead.
    • 
    
  • Writers take turns. Every append and every removal holds .chaos-kb/append.lock, so two agents writing at once keep both facts.
    • 
    
  • Never half a note. A write goes through a temporary file that has the note's permissions from the start, a flush to disk and a rename.
    • 
    
  • Nothing outside the vault. Paths are relative with visible segments; a symlinked folder or note, or a folder resolving outside the vault, is refused.
    • 
    
  • No damage to odd files. A read-only note, or one that is not valid UTF-8, is refused, not rewritten.
    • 
    
  • Code is not a heading. A # line inside a code fence or the front matter never counts as a heading.
    •
