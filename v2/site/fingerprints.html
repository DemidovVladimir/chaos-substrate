Fingerprints and exact check

A fingerprint is a hash of one block's words. Each note gets one hash over its fingerprints. The same words take one lookup, and a note that keeps its hash did not change.

  • hash: BLAKE3, 32 bytes, 64 hex characters
  • tag 0x00 for words, 0x01 for a list of hashes
  • 2 levels: notes and block fingerprints
  • 0 model calls on the exact path

One sync, then one lookup

From words to note hashes

A hash is a short, fixed-size value computed from data: equal data gives an equal hash. chaos-kb hashes the words of every block, and then each note's list of block hashes.

Why it stops at notes

No hash for the whole vault

Earlier versions also hashed every note hash into one root hash, a Merkle tree, and put the root in every answer. One value for a whole collection pays off when someone must check that collection without holding it, the way an Ethereum light client checks an account against the state root in a block header. chaos-kb has no such reader. The agent asks the same index file that holds the notes, and sync compares the notes one by one anyway, so the root only repeated what the lists added, changed and removed already say. It was removed.

The fingerprints and note hashes did not change, so an index file written by an earlier version still opens, and the next sync reports nothing new.

What a sync sees

Edits and their hashes

The sync report lists the notes added, changed and removed. Empty lists mean nothing changed.

  • sameformatting onlyBold, a list marker, extra spaces: every hash stays. The chunk text changed, so that chunk is embedded again.
  • changeda word or a symbol editedThe note's hash changes. Every other note keeps its hash.
  • changeda fact moved under another headingIts label changes, so the note changes.
  • changedtwo facts swappedOrder is part of a note, so the note changes.
  • addeda note renamedThe new path is added and the old one removed. The note hash itself stays the same.
  • removeda note deletedIts fingerprints leave the exact index.
Enforced in code

Guarantees

  • Formatting never moves a hash. Blocks are hashed as plain words, so Markdown syntax, case, spacing and sentence punctuation do not count.
  • Symbols that carry meaning count. A+ and A-, ≤ and ≥, C++ and C# stay different facts.
  • Words, order, headings and paths count. Change the words, their order or a heading and the note's hash changes; change the path and the note shows as added and removed.
  • No mix-ups by construction. Hashed words and lists of hashes start with different tag bytes, every label carries its length, and one heading named Car > Oil is not two nested headings.
  • Blank blocks are not knowledge. A rule or an empty item never enters a note hash or the exact index.
  • The exact path is free. It reads the stored fingerprints and never calls the embedding model.
  • Hashes are always whole. They print as 64 lowercase hex characters, and nothing shorter is accepted.
Try it

Watch the note lists

On copies of the example vault. The edits were made between the commands. JSON is shown condensed.

$ chaos-kb sync
{ "added": ["Car.md", "Communication.md", "Health/Allergies.md"], "embedded": 5, ... }
# Car.md line 8 becomes: **I change** the engine oil every 10 000 km!
$ chaos-kb sync
{ "changed": [], "embedded": 1, ... }
# now: **I change** the engine oil every 15 000 km!
$ chaos-kb sync
{ "changed": ["Car.md"], "embedded": 1, ... }
$ mv Communication.md Talking.md && chaos-kb sync
{ "added": ["Talking.md"], "removed": ["Communication.md"], "embedded": 1, ... }
$ rm Health/Allergies.md && chaos-kb sync
{ "removed": ["Health/Allergies.md"], "notes": 2, "chunks": 4, "embedded": 0, ... }
$ chaos-kb check "allergic to penicillin"
{ "known": false, "presence": "absent", "matches": [], "score": 0.008867578580975533, ... }
# a fresh copy of the example vault
$ chaos-kb remember "Rhesus factor: A+" --note Health/Allergies --heading Blood
{ "stored": true, "embedded": 1, ... }
$ chaos-kb check "rhesus factor: A+"
{ "known": true, "presence": "exact", "matches": [ { "note": "Health/Allergies.md", "section": "Allergies > Blood", "lines": [7, 7] } ], ... }
$ chaos-kb check "Rhesus factor: A-"
{ "known": true, "presence": "similar", "score": 0.5398281812667847, "matches": [ { "note": "Health/Allergies.md", "lines": [7, 7], ... } ], ... }
$ chaos-kb remember "Rhesus factor: A-" --note Health/Allergies --heading Blood
{ "stored": true, "embedded": 1, ... }

The rename embedded one chunk because a chunk's context line starts with the note title (see Chunks, embeddings and search). Its words, and so its note hash, did not change. By meaning, A- reads close to the stored A+, so similar means "read the match". The fingerprints differ, so the exact path never confuses them and remember stores A- as a new fact.
