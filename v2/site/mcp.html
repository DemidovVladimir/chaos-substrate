Agents and MCP

MCP, the Model Context Protocol, is how an agent calls tools. chaos-kb mcp serves the seven tools over stdio. Their names, descriptions, schemas and the README reference all come from the command-line definition.

  • 7 tools: kb_sync, kb_remember, kb_forget, kb_check, kb_search, kb_topics, kb_read
  • 4 methods: initialize, ping, tools/list, tools/call
  • 3 protocol revisions, newest 2025-11-25
  • 0 files opened before the first call
  • 手 tools the server and its replies
  • 印 hash the generated roster and argv
  • 守 guard argument checks
  • data the knowledge base

From a tool call to a report

stdio means the agent starts the server as a child process and talks through its standard input and output. Messages are JSON-RPC 2.0: one JSON object per line.

One source per fact

From clap to a JSON schema, and back

Each argument's JSON type is read from how clap parses it. A call is turned back into a command line, so defaults and checks live in one place.

clap argumentJSON schema
a flag, such as --dry-runboolean
an unsigned integer, such as --limitinteger, minimum 0
a float, such as --min-scorenumber
a list, such as idsarray of string, minItems 1 when required
anything else, such as querystring
a default valuedefault
a required positionallisted in required
every tooladditionalProperties false
Call argumentsParsed as
kb_sync {"dry_run": true}sync --dry-run
kb_check {"query": "oil", "min_score": 0.5}check --min-score=0.5 -- oil
kb_remember {"text": "…", "note": "Health/Allergies"}remember --note=Health/Allergies -- …
kb_forget {"text": "Tea, no sugar.", "note": "Inbox.md"}forget --note=Inbox.md -- Tea, no sugar.
kb_search {"query": "oil", "limit": null}search -- oil, so the default 5 applies
kb_read {"ids": ["Health/Allergies.md:3-3", "Car.md:8-8"]}read -- Health/Allergies.md:3-3 Car.md:8-8, in that order
kb_read {"ids": ["Car.md:8-8", 7]}refused: `ids` must be a list of strings
{"vault": "/tmp"}refused: not an argument of the tool

Positionals go after --, so a query that starts with - is still text. A list's items stay in the order given. The same definition writes the tool reference in README.md, and cargo test fails when that block drifts.

Replies

What comes back

  • resulta requestOne reply line, with the same id.
  • isErrora bad argument or a failed toolA normal result whose text is the error, so the model can fix the call.
  • silenta notification or a blank lineNo reply. A message without an id is a notification.
  • silenta responseNo reply. A message with result or error and no method answers a request; replying to it would be an error.
  • -32602unknown tool, or no tool nameunknown tool: kb_nope
  • -32601unknown methodmethod not found: resources/list
  • -32600not one JSON object, or no methodA JSON array gives expected one JSON-RPC object; an id alone gives a request needs a method.
  • -32700not JSON at allparse error: …, with id null.
Enforced in code

Guarantees

  • Instant handshake. Nothing is opened or contacted before a tool is called.
  • One definition. Tool names, descriptions, schemas and defaults come from the clap definition in src/entry/cli.rs. One argument list in src/entry/tools.rs writes both the MCP schema and the README block, and the README is tested against it. The dashboard calls the tools through the same list.
  • A call cannot move the server. Vault, index, embeddings URL and model are not tool arguments.
  • Unknown keys are refused. The error names the arguments the tool takes.
  • stdout carries replies only. Each reply is one line, flushed at once.
  • The API key stays in the environment. It is read only from CHAOS_KB_EMBED_API_KEY, never from a flag or an argument.
Try it

Connect an agent

The first command registers the server with Claude Code (from README.md). The others talk to it by hand on the example vault.

$ claude mcp add chaos-kb -- chaos-kb --vault ~/Knowledge mcp
$ echo '{"jsonrpc":"2.0","id":7,"method":"ping"}' | chaos-kb mcp
{"id":7,"jsonrpc":"2.0","result":{}}
$ echo '{"jsonrpc":"2.0","id":10,"method":"tools/call","params":{"name":"kb_search","arguments":{"query":"winter tyres","limit":1}}}' | chaos-kb mcp
{"id":10,"jsonrpc":"2.0","result":{"content":[{"text":"{\"hits\":[{\"lines\":[12,12],\"note\":\"Car.md\",\"score\":0.5618284940719604,\"section\":\"Maintenance > Tyres\",\"text\":\"Winter tyres go on in November.\"}]}","type":"text"}],"isError":false}}
$ echo '{"jsonrpc":"2.0","id":11,"method":"tools/call","params":{"name":"kb_read","arguments":{"ids":["Health/Allergies.md:3-3","Car.md:8-8"]}}}' | chaos-kb mcp
{"id":11,"jsonrpc":"2.0","result":{"content":[{"text":"{\"missing\":[],\"passages\":[{\"id\":\"Health/Allergies.md:3-3\",\"section\":\"Allergies\",\"text\":\"Allergic to penicillin.\"},{\"id\":\"Car.md:8-8\",\"section\":\"Maintenance > Oil\",\"text\":\"I change the engine oil every 10 000 km.\"}]}","type":"text"}],"isError":false}}
$ echo '{nope' | chaos-kb mcp
{"error":{"code":-32700,"message":"parse error: key must be a string at line 1 column 2"},"id":null,"jsonrpc":"2.0"}

These commands assume CHAOS_KB_VAULT points at the vault. Every tool also works as a plain command: chaos-kb check "…" prints the same report.
