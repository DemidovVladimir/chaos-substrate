Topics and read

Before an agent does a task for you, it should know what your notes say that changes the result, and nothing else. topics lists the passages near the task as one short line each, without their text. A small, fast model, the searcher, keeps the lines that matter, and read fetches only those passages.

  • 8 lines by default, best first
  • 100 characters at most per gist
  • 1 embedding call for topics, 0 for read

Why the searcher judges, not a number

The four tasks of tests/e2e.rs, with every score topics returned on its example vault (embeddinggemma, Apple M4). Green bars mark the passages that matter for the task, judged by hand. Move the line: a passage at or above it is kept.

0.38

The line starts at check's 0.38, which drops everything: no passage of the four tasks reaches it. No line works for all four. The antibiotic task needs the line above 0.182, the vitamin D passage, while the database task needs it at or below 0.151, its only useful passage. The ranking is right every time: the passage that matters most comes first. So topics returns the ranked lines and leaves the cut to the searcher. Passage ids

What an id can be

An id is note:first-last: the note's path in the vault, then the first and last line of the passage.

  • readCar.md:8-8A stored passage: its section and full text come back.
  • piecesa cut blockA block longer than 1200 characters is cut into pieces with the same lines. topics lists the id once; read returns every piece in reading order.
  • onceasked twiceThe same id twice in one call is read once.
  • missingCar.md:7-8Well formed, but no passage has those lines: the note changed or is gone. It is listed under missing, never guessed; list the topics again.
  • refusedCar.md · Car.md:9-8No line range, a line 0, or a first line after the last: the call fails and names the shape.
  • exactone colonA note path never contains :, so the last colon always splits note from lines.
Enforced in code

Guarantees

  • No text in the list. topics returns ids, sections, scores and gists only, so the searcher reads a few hundred characters, not the passages.
  • The same ranking as search. Every stored vector is compared; nothing is approximated, and nothing is dropped for its score.
  • read embeds nothing. It looks ids up in the index, so it needs no model and still works after a model change, until the next sync.
  • The order you asked for. Passages come back in the order of the ids, also over MCP, where the ids are a JSON array.
  • Pieces read in order. The index stores each passage's position from sync, so the pieces of a cut block come back as they read in the note, not in hash order.
  • Nothing is guessed. An id the index does not hold is reported under missing; a malformed id fails the call.
Try it

Topics and read on the example vault

Run on the example vault with embeddinggemma on an Apple M4. JSON is shown condensed. On a vault of 503 notes, topics took 0.10 s and read 0.03 s (README § Speed).

$ chaos-kb topics "Prescribe an antibiotic for my sore throat." --limit 3
{ "topics": [
  { "gist": "Allergic to penicillin.", "id": "Health/Allergies.md:3-3", "score": 0.23157881200313568, "section": "Allergies" },
  { "gist": "When someone explains something to me, I want a concrete example first and the general rule after.",
    "id": "Communication.md:3-3", "score": 0.06845960021018982, "section": "How I communicate" },
  { "gist": "--- car: Toyota Corolla 2018 ---", "id": "Car.md:1-3", "score": 0.06677795201539993, "section": "" } ] }
$ chaos-kb read Health/Allergies.md:3-3
{ "missing": [], "passages": [ { "id": "Health/Allergies.md:3-3", "section": "Allergies", "text": "Allergic to penicillin." } ] }
$ chaos-kb read Car.md:8-8 Car.md:7-8
{ "missing": ["Car.md:7-8"], "passages": [ { "id": "Car.md:8-8", "section": "Maintenance > Oil", "text": "I change the engine oil every 10 000 km." } ], ... }
$ chaos-kb read Car.md
error: `Car.md` is not a passage id (note:first-last, like `Car.md:8-8`)
$ chaos-kb topics "  ---  "
error: the task is empty (no letters or digits)

The searcher keeps only the allergy: the other two lines would not change a prescription. Car.md:7-8 is well formed, but the oil passage sits on line 8 alone, so it is reported, not stretched to fit.
