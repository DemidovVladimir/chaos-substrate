Install and run chaos-kb

chaos-kb is a personal knowledge base for agents: Markdown notes in, quick "is this known?" answers out. Install one binary, pull one local model, point it at a folder of notes, and connect it to Claude Code or Codex.

  • builds with Rust 1.91 or later
  • model embeddinggemma on Ollama, localhost:11434
  • 8 tools for agents: kb_sync, kb_remember, kb_forget, kb_check, kb_search, kb_topics, kb_read, kb_instances
  • one vault or several, each by name
  • index in <vault>/.chaos-kb/, safe to delete
  • notes your vault, the only copy of your knowledge
  • 手 tools chaos-kb and its eight tools
  • 心 model the local embedding model
  • data the index file
Setup, then daily use

From nothing to an agent that remembers

The chaos-kb binary itself is built from the v2/ folder of the chaos-substrate repository: cargo install --path v2 from the repository root.

Connect your agent

Register the MCP server once

The agent runs chaos-kb --vault <folder> mcp as a child process and talks to it over stdin and stdout. You only tell it the command.

$ claude mcp add --scope user chaos-kb -- chaos-kb --vault ~/Knowledge mcp
$ claude mcp list

--scope user makes the server available in every project; without it, only in the current one. Everything after -- is the command Claude Code runs. Inside a session, /mcp shows the server and its eight tools.

$ codex mcp add chaos-kb -- chaos-kb --vault /Users/you/Knowledge mcp
Added global MCP server 'chaos-kb'.

That command writes these lines to ~/.codex/config.toml (example path), so you can also add them by hand:

[mcp_servers.chaos-kb]
command = "chaos-kb"
args = ["--vault", "/Users/you/Knowledge", "mcp"]
{
  "mcpServers": {
    "chaos-kb": {
      "command": "/Users/you/.cargo/bin/chaos-kb",
      "args": ["--vault", "/Users/you/Knowledge", "mcp"]
    }
  }
}

Most desktop clients take this shape (example paths). An app started from the Dock may not see your shell's PATH, so give the full path to the binary. Settings such as CHAOS_KB_EMBED_MODEL go in the client's env block.

When the server starts, it tells the agent how to use the tools: list the topics before a task and read only what matters, check before asking the user, remember one fact per call, forget a wrong fact in its stored words before remembering the correction, and sync after notes are edited. It also says that several knowledge bases may be configured, that instances lists them, and that instance picks one for a call.

Personal and work

Several knowledge bases, one server

Repeat --vault as NAME=PATH, once per folder of notes. The first one is the default; --instance NAME makes another one the default. Each keeps its own index inside its own folder.

$ claude mcp add --scope user chaos-kb -- chaos-kb --vault personal=~/Knowledge --vault molecule=~/development/molecule/molecule/knowledge mcp

You writechaos-kb reads
--vault ~/Knowledgeone knowledge base, named default: the same as before there were names
--vault personal=~/Knowledgepersonal, in your home folder's Knowledge. The shell leaves ~ alone after =, and so does an MCP client's config, so chaos-kb reads it as your home folder
--vault /a/b=cone path, because /a/b is not a name. A name holds only letters, digits, _ and -
two --vault without namesrefused: both would be named default
--index with two vaultsrefused: each keeps <vault>/.chaos-kb/index.redb
CHAOS_KB_VAULTone value, in either form

The paths are examples. instances opens no folder, so it works while Ollama is down. Every other tool takes instance to use another knowledge base for one call; on the command line the global --instance does that. With more than one instance, every report says which one answered or was written to, as "instance": "molecule" above; with one, reports carry no instance. The dashboard shows a switch between them.

Day to day

What to run, and when

Every tool is also a plain command that prints JSON. An agent calls the same thing as kb_ plus the command name.

WhenRunWhat happens
You edited notes yourselfchaos-kb syncOnly new or edited passages are embedded; --dry-run shows what would change.
Is this already known?chaos-kb check "…"exact, similar or absent, with where it sits.
What do my notes say?chaos-kb search "…"The best passages with note, section, lines and text; 5 by default.
A new fact to keepchaos-kb remember "…" --note Health --heading BloodAppended under that heading and indexed; skipped when the same words are stored. Without --note it goes to Inbox.md.
A stored fact is wrongchaos-kb forget "…" --note HealthEvery block with the same words is removed from the note and the index; then remember the correction. Without --note, from every note.
Which knowledge bases are there?chaos-kb instancesEach one's name, vault folder and index file, with the default marked. Opens nothing.
Ask another knowledge basechaos-kb --instance molecule check "…"Any tool, on the instance named; an agent passes instance instead.
You want to see what is storedchaos-kb dashboardA page at http://127.0.0.1:7341 (--port picks another): your notes next to the index, with add, replace and remove. See The dashboard.
You switched the modelchaos-kb syncEverything is embedded again; vectors of two models are never compared.
You updated chaos-kbcargo install --path v2The new binary replaces the old one. An index of an older layout is rebuilt by the next sync.
The index looks wrongdelete <vault>/.chaos-kb/, then chaos-kb syncRebuilt from the notes, which are never touched.
Settings

Flags and environment

Each setting is a flag before the command, or an environment variable. Defaults are the ones in the code.

FlagEnvironmentDefault
--vault, as PATH or NAME=PATH, repeatableCHAOS_KB_VAULT, one valuenone: required
--instanceCHAOS_KB_INSTANCEthe first --vault
--index, with one --vault onlyCHAOS_KB_INDEX<vault>/.chaos-kb/index.redb
--embed-urlCHAOS_KB_EMBED_URLhttp://localhost:11434/v1
--embed-modelCHAOS_KB_EMBED_MODELembeddinggemma
noneCHAOS_KB_EMBED_API_KEYunset; only for an embeddings API that needs a key

A cloud embeddings API receives your note text. The key is sent only over https://, or over plain http:// to this machine, and it is never printed.

When something is off

Every message names its fix

Real messages from chaos-kb. Over MCP the agent gets the same text as a tool error, so it can tell you.

MessageDo this
error: set --vault or CHAOS_KB_VAULTExport CHAOS_KB_VAULT, or pass --vault before the command.
error: vault folder Nowhere not found: No such file or directory (os error 2)Create the folder, or fix the path.
error: two vaults are named `default`: give each one its own name, as --vault NAME=PATHWrite --vault personal=~/Knowledge --vault molecule=….
error: no instance is named `work`; the instances are `personal`, `molecule`Use one of the names listed, in --instance or in a call's instance.
error: --index (CHAOS_KB_INDEX) takes a single --vault: with several, each keeps its index at <vault>/.chaos-kb/index.redbDrop --index (and unset CHAOS_KB_INDEX).
error: the index is empty: run `chaos-kb sync` firstRun chaos-kb sync.
error: embeddings request to http://127.0.0.1:9/v1/embeddings failed: io: Connection refused (os error 61)Nothing listens at the embeddings URL (here a closed port). Start Ollama: open the app, or run ollama serve.
error: embeddings API returned HTTP 404: {"error":{"message":"model \"no-such-model\" not found, try pulling it first","type":"not_found_error","param":null,"code":null}}Pull the model (ollama pull embeddinggemma), or fix --embed-model.
error: the index was built with embedder `embeddinggemma|gemma-retrieval-v1` but `all-minilm|plain-v1` is configured: run `chaos-kb sync` to re-embedSet the model back, or run chaos-kb sync to re-embed everything with the new one.
error: listening on 127.0.0.1:7341: Address already in use (os error 48)Another program, often a dashboard already running, holds the port. Open that one, or start this one with chaos-kb dashboard --port 7342.
zsh: command not found: chaos-kb (from your shell)Add ~/.cargo/bin to your PATH, or use the full path.

Asking by the same words works even while Ollama is down: check finds stored words without the model, and read fetches passages by id. Only search, topics, check by meaning and sync need it.

Answers

What check tells you

  • exactthe same words are storedFound without the model; matches lists every place they sit.
  • similara passage scores at least 0.38Probably known: read it with search before relying on it.
  • absentnothing reaches the linescore still shows the best one. Close to 0.38? Search before you ask, as in the run below.
  • errorsomething is missingThe message names the fix; see the table above.
Enforced in code

Guarantees

  • Local by default. Embeddings go to Ollama on localhost, and proxy settings are never used for this machine.
  • Your notes change only through remember and forget. remember appends and refuses to change existing text; forget removes blocks with the same words and refuses when the rest would read differently. Both write through a temporary file and a rename.
  • The server starts instantly. chaos-kb mcp opens nothing until a tool is called, so it starts before the vault or Ollama is ready.
  • An agent cannot move it. Vault folders, index, embeddings URL and model are not tool arguments. instance only picks one of the vaults you configured.
  • The CLI, the server and the dashboard can run together. They take turns on lock files instead of failing.
  • The index is derived. Delete .chaos-kb/ and sync rebuilds it from the notes.
